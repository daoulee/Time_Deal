### 2. 인증이 DeviceId(UUID)에만 의존
`user_id` / `store_id` 전부가 `DeviceId.value`(SharedPreferences UUID).  
Supabase Auth 로그인 UI는 있지만 실제 DB 쿼리에서 Auth `user.id`를 사용하지 않음.

**결과**: 앱 재설치 시 모든 예약·딜 기록 연결 끊김.  
**조치**: `Supabase.instance.client.auth.currentUser?.id`로 전환 필요. (대회 이후 작업)

---

### 3. RLS 정책 OR true — ✅ 완료 (2026-08-21)
모든 정책에 `OR true`가 붙어 실질적 차단 없음.  
→ `supabase_setup.sql` 수정 완료. **대시보드 SQL Editor에서 실행 필요.**

적용된 보호:
- `deals` DELETE 완전 차단
- `deals` UPDATE 만료 딜 수정 차단
- `reservations` DELETE 완전 차단
- `reservations` INSERT/UPDATE 유효값 검증

```sql
-- 대시보드 실행 전 기존 정책 먼저 삭제
DROP POLICY IF EXISTS "deals_insert_own" ON deals;
DROP POLICY IF EXISTS "deals_update_stock_only" ON deals;
DROP POLICY IF EXISTS "reservations_insert" ON reservations;
DROP POLICY IF EXISTS "reservations_select_own" ON reservations;
DROP POLICY IF EXISTS "reservations_update_all" ON reservations;
DROP POLICY IF EXISTS "wishlists_select_own" ON wishlists;
DROP POLICY IF EXISTS "wishlists_insert_own" ON wishlists;
DROP POLICY IF EXISTS "wishlists_update_own" ON wishlists;
DROP POLICY IF EXISTS "wishlists_delete_own" ON wishlists;
-- 이후 supabase_setup.sql 전체 실행
```

### 4. cancel() 재고 복구 레이스 컨디션 — ✅ 완료 (2026-08-21)
클라이언트 값 기반 `+1` UPDATE → 동시 취소 시 복구 1번만 됨.  
→ `increment_stock` RPC 추가 및 `cancel()`에 적용 완료.

## 🟡 주의 (Warning)

### 5. `Deal.copyWith()` — distanceKm만 지원
다른 필드(remainingStock 등) 변경 시 객체 전체 재생성 필요.  
→ 전체 필드 copyWith 구현 권고. (대회 이후)

### 6. 프로필 사진을 deal-images 버킷에 저장
`profiles/` 경로를 `deal-images` 버킷에 혼재 저장.  
→ `profiles` 전용 버킷 분리 권고. (대회 이후)

### 7. Realtime 이벤트마다 전체 목록 재조회
변경 내용 무시하고 `_load()` 전체 재실행 → 딜/예약 증가 시 네트워크 낭비.  
→ `PostgresChangePayload` 파싱으로 로컬 리스트 직접 갱신 권고. (대회 이후)

### 8. WishlistProvider도 DeviceId 의존
문제 #2와 동일 패턴. 앱 재설치 시 찜 목록 초기화.  
→ #2 해결 시 함께 수정.

### 9. 예약 실패 시 UI 에러 피드백 없음
`lastError` 필드에만 저장, 화면에 표시 안 됨. 사용자는 예약이 됐다 사라지는 현상만 경험.  
→ SnackBar 또는 다이얼로그로 에러 노출 권고.

## 🟢 개선 권고

### 10. decrement_stock RETURNS void
재고가 0이어서 UPDATE 0 rows가 됐는지 클라이언트가 알 수 없음.  
→ `RETURNS boolean`으로 변경 권고.

### 11. DealProvider.createFromForm() storeId가 DeviceId
딜 등록 시 `store_id`도 DeviceId 의존. #2 해결 시 함께 수정.

### 12. E2E 테스트 미완료
소비자 ↔ 사장님 양방향 동기화 리허설 3회 이상 필요. **대회 전 필수.**
